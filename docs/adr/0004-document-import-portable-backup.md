# ADR-0004：隔离文档解析与完整书库备份

- 日期：2026-10-17（Asia/Shanghai）
- 状态：已实现，验证范围见评测记录
- 对应：P0 IMP / DAT；AC-02、AC-03、AC-15、AC-16、AC-28

## 问题与决策

既有 TXT 预览和 SQLite backup API 不等于 EPUB/PDF 支持或完整项目备份。大文件不能以 base64 填进 16 MiB stdio 帧；PDF 内容流可能消耗远大于文件大小的内存；复制正在使用的 SQLite 主文件会丢掉 WAL 中的数据。

继续使用现有 Book、正文/规划修订和分支快照。Rust 从原生选择框获得文件，将限量读取的内容暂存为随机标识；UI 只获得任务标识。Python 校验标识和目录边界，使用专用子进程解析 EPUB、PDF 或处理备份。子进程入口只支持固定操作，不提供通用命令执行。开发/测试的小文件兼容 base64 请求，原生大文件走暂存资产。

文件操作立即返回 operation_id，阶段与终态保存在受控 operations 目录；UI 轮询 file.get，file.cancel 终止子进程。任务重启后标记中断，不自动重跑。记录不含 PDF 密码、任意本机路径或凭据。启动清理受控 inbox 中的临时副本；它们不是正式 sources 原文件。已完成备份保留在 outbox，应用重开后可再次保存最近结果。

## 格式与限制

EPUB 使用 zipfile、lxml 与 BeautifulSoup，按 package/spine 顺序提取纯文本，用 EPUB 3 nav / EPUB 2 NCX 作为标题提示，保留书名、作者、封面资源定位和正文资源定位。先校验整个 ZIP 的路径、符号链接、重复条目、加密、解压量与压缩比。XML 关闭网络、外部 DTD 加载和实体解析；禁止实体声明/引用。脚本、样式和嵌入内容移除后只保存字符串，UI 不渲染原始 HTML，也不请求远程资源。外部 XHTML DOCTYPE 不加载；普通无实体的 DOCTYPE 可接受。固定版式和加密资源明确拒绝，媒体覆盖仅提示限制。

PDF 使用 pypdf，页数读取和每一页分别进入受限子进程。单页墙钟上限 8 秒，页数读取 10 秒，整书 180 秒；支持资源限制的平台另设 CPU 20 秒、地址空间 2 GiB。超时/异常退出可终止和记录遗漏，不能把半份结果静默当完整书。文本缺失或明显乱码返回 OCR_REQUIRED；不实施 OCR。用户填写的密码只在内存和私有 stdin 中传递。每页保存页码定位。仅保守修复中文软换行和英文连字符断行；重复页眉/页脚处理由用户可选开启，至少三页重复才尝试处理，并显示提示。

本轮保护值：TXT 10 MiB；EPUB/PDF 文件 100 MiB；EPUB 解压总量 500 MiB、单条目 50 MiB、10,000 条目、压缩比 1000；PDF 2,000 页、单页内容流 10 MiB、单页提取文本 1 MiB；EPUB/PDF 总提取文本 8 MiB。达到页数上限不保证能在整书时限内处理完成。预览不创建 Book；PDF 有遗漏时，后端和 UI 都要求明确接受不完整导入。确认导入复用原有事务与幂等逻辑，原始字节以 SHA-256 保存。

## 完整备份与恢复

`.narravo` 是 ZIP，包含版本 1 的 manifest、schema 版本、独立 SQLite 一致性快照、SHA-256/大小、sources 原始资产，以及可选 audio 资产。备份覆盖整个当前书库，包含空作品、全部修订、规划、分支、候选、接纳决策及现有任务。当前尚未实现书签/阅读进度，备份不会虚构这些数据。

快照通过 SQLite backup API 创建，目标切到 DELETE journal 并显式关闭连接，清理后 VACUUM，避免依赖未归档的 WAL 或保留已删配置的空闲页。可移植备份排除活动 providers/preferences；历史生成保留协议/模型/参数来源，但移除服务地址、名称、配置 ID 和凭据存在标志。系统凭据库从不进入此流程。活动远端任务转为 UNKNOWN_OUTCOME，本地活动任务转为中断；不含音频时同时移除音频索引及任务播放计划。费用/用量记录仍保留。

恢复先在新目录流式读取清单列出的文件，验证 ZIP、路径、文件集合、大小、全部校验和、数据库 schema 白名单/版本、完整性、外键、JSON 修订/分支/候选/决策引用、正文计数和音频格式。文件与解压总量均限制为 1 GiB，20,000 条目；当前只支持相同数据库 schema 0003，版本不兼容时拒绝，不擅自改写备份。校验失败不动当前书库。

校验通过后仍等待用户点击产品中的“恢复为独立书库并切换”。此时必须没有活动模型、语音或文件任务。预先保存恢复前书库标识，原子写入并同步 active-library.json，然后切换内存连接；重启读取该指针。当前书库不删除、不合并、不覆盖。界面可切回恢复前书库，也可再次进入恢复书库。恢复端没有 providers/preferences，因此不会继承发送授权或触发远端重试。

## 替代方案与代价

- 在主引擎内直接解析：异常资源消耗会阻塞取消和 RPC，故使用可终止子进程。
- 直接覆盖当前 library.db：文件/数据库没有统一原子事务，且易损坏 WAL，故使用独立目录和原子选择指针。
- 把 ID 重映射后合并所有作品：涉及历史 JSON、候选幂等键和分支关系，复杂度与风险高，P0 不做。
- 全量复制数据目录：会混入临时文件、服务地址和残缺音频，故按一致性快照引用的资产白名单打包。

备份未加密，含作者秘密；UI 如实提示。暂未提供保留库/历史备份的空间管理界面，不自动删除它们。逐页子进程启动有性能开销；源定位仍是章节/资源 body/页码级，未提供 PDF 坐标、EPUB 元素细粒度锚点或图片/封面显示。恢复格式后续升级需要显式兼容代码和升级测试；本轮没有业务 schema 迁移。

## 验证

隔离临时目录测试覆盖 EPUB spine/导航/恶意包，PDF 文本/扫描/混合/密码，WAL 一致性、空作品/分支/作者规划/接纳历史、可选音频、服务配置排除、活动远端请求冻结、损坏版本/校验和/schema/JSON 引用、磁盘写入失败、取消和重启选择书库。真实引擎的浏览器流程覆盖导入与恢复；原生打包和独立 sidecar 另行验证，不能由浏览器测试替代。
