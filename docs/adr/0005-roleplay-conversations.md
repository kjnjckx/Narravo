# ADR-0005：独立角色会话与有界群聊，复用模型和语音底座

- 日期：2026-10-17，Asia/Shanghai
- 状态：设计已实施；确定性与本机原生替身验证，真实模型/听感/时延未验收
- 对应：RPL / RCH / RGR / RTV / CTX / PRO / DAT；PRD 第 5、8、12、13、19 节；AC-32 至 AC-49
- 前置：[ADR-0001](0001-unified-writing-project.md)、[ADR-0002](0002-local-writing-foundation.md)、[ADR-0003](0003-provider-integration.md)；已有导入/备份决策见 [ADR-0004](0004-document-import-portable-backup.md)

## 问题

用户要求自定义聊天对象及其人设，与单个或多个角色互动，并按上下文、人设与语境实时朗读回复。角色可独立于小说存在，群聊需要可控制的发言顺序。小说正文使用 AI 候选接纳规则，而普通聊天若每条都要求接纳，会破坏对话体验；直接复用正文表又会污染作品事实和听书内容。

实施前的代码提供按章写作、规划修订、模型配置与协议 adapter、固定旁白音色、完整片段验证后播放，以及导入和书库备份底座。当时没有聊天会话、角色发言调度、情境表达或增量封句管线。不能把当前能力当成实时聊天语音，也不应为每个虚拟角色新增进程或自治 Agent。

## 决策

### 1. 独立会话根与角色身份，复用基础能力

新增独立于 Book 的 RoleplayCharacter 和不可变 PersonaRevision；Conversation 引用角色、可选用户身份、场景、成员、声音与记忆修订。仍使用同一个 Python 业务写入进程、SQLite、任务引擎、provider adapter、系统凭据库和音频资产层，不新增 HTTP 业务服务、云数据库或多代理框架。

作品 Character 保留 book_id 约束。从作品创建扮演角色时显式复制用户选定且可见的字段，保存 source_character_ref/source_snapshot，不将两者冒认为同一实体或自动双向同步。复用角色字段 schema、声音编排和稳定 ID 原则；VoiceBinding 扩展明确的 book_character / roleplay_character / conversation_member 作用域，引用稳定目标及修订。同名对象不合并，成员 ID 不由模型自由文本姓名推断。

角色库更新产生新修订，不追溯修改历史会话。会话主动应用新版时生成新快照；进行中的轮次先取消再更新依赖。归档或移出不删除仍被历史引用的角色修订。

### 2. 聊天历史与小说候选采用不同提交语义

用户消息直接保存，首次完整且通过本地校验的 AI 回复自动成为会话历史。小说正文和规划仍须显式接纳；会话没有写入小说正文、摘要事实或书籍 Lorebook 的默认权限。

消息有稳定 ID、回复变体和不可变内容修订，ConversationSnapshot 以单父历史路径选择版本。流式接收保存检查点和不可变封句片段；中断部分默认不进入后续生成上下文，用户可明确使用。重试保留当前选择，生成独立变体，用户再选择。编辑旧消息或改选变体派生新路径，后续消息留在旧路径，受影响记忆重新计算。

所有历史选择和依赖更新均校验 expected_snapshot 并本地幂等；旧任务只能保存到原快照。不同于本地写入幂等，云端调用不承诺恰好计费一次。

### 3. 群聊由有限队列调度

P0 支持 @指定、轮流、全员和情境选择，默认 @指定。初始人数上限 8；每批次每成员最多回复一次、最多 8 条，情境模式默认选 1–3 人。调度只输出稳定 member_id 队列，本地检查禁言、资格、重复和数量；无效输出停止并让用户指定，不无限修复。

每位成员串行生成，后续成员只读取已完成且对其可见的前序回复。每批次由用户消息或显式继续触发，队列完成即停，不允许角色回复递归触发下一轮。轮次共享累计调用/token/字符/费用预算，情境选择和语气分析也计入；取消持久化，停止后不得提交新的下游请求。

### 4. 按目标角色构造 chat_scoped 上下文

请求只读取本会话、当前路径、已选择消息版本、目标角色人设、所选用户身份、共享场景与有来源的可见记忆。自己的私有知识不注入其他角色请求，发言选择模型也只见公开资料。新成员默认仅见加入后消息；摘要和检索必须遵守相同来源与可见范围。

chat_scoped 不继承小说 author_plan/full_rewrite 权限。复制小说角色默认排除未来秘密，作者资料须另行明确选入并提示会发送给模型。模型可能披露自己收到的内容，不能把私有范围标签宣传为绝对防泄露。人设、示例和消息只能影响文本内容，不授予工具或文件权限。

### 5. 实时语音先采用增量封句加完整短片段播放

文字增量经过 Unicode 安全分句，封存短句后绑定回复变体、稳定片段 ID、文本范围/哈希和声音计划，再交给 TTS。首句无需等待整条消息生成完毕。服务响应仍先验证、落盘并提交资产状态，之后才发 audio.ready；当前完整文件合同保持清晰。

首次按人设音质描述和可用声音提出建议，经用户确认或使用预选默认声音。voice_id 保持身份稳定，语境改变已支持的表达方式；人工锁定与单句覆盖优先。语气标注本地校验、费用和延迟单独记录；不支持表达参数时明确回退普通语气，TTS 失败不终止文字。

TTS 默认只接收 spoken text 和必要表达参数，不传整张人设或完整聊天。原生流式音频 chunk 属于后续能力，必须新增可验证的 chunk 合同，不提前将半文件标 ready。

### 6. 独立播放清单、打断与背压

共用播放器和资产，但会话播放清单必须绑定 conversation_snapshot、turn、message、reply_variant、segment_revision、文本哈希、计划修订与 playback_epoch。跨会话、变体、轮次及 epoch 的旧结果拒绝入当前队列。

停止语音立即静音、清空本轮队列并停止后续自动合成，文字可继续；停止本轮再取消文本、调度和全部下游任务。新消息停止旧轮后发送，切换会话停止旧会话自动发声。初始最多 3 个待播片段、每服务最多 1 个聊天 TTS 在途，并服从共用服务限制；积压时暂停合成但继续保存文字，不丢句、不无限预取。

音频缓存键复用完整表达输入指纹，播放引用另做源版本校验。重启可恢复文本、资产和终态，不自动续聊、重放未知远端请求或发声。

## 比较过的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 每个聊天对象建成一本空小说 | 伪造作品结构，聊天与正文、接纳、计数和事实来源混杂 |
| 所有角色共用一个含完整人设的群提示词 | 私有知识跨角色暴露，发言身份和记忆难以约束 |
| 为每个角色创建自治 Agent/进程 | 增加编排和取消复杂度，容易无限互聊，有限队列足以支撑 P0 |
| 每条回复都要求接纳后才继续 | 增加无必要的聊天步骤；用变体选择和历史路径保留可恢复性 |
| 等整条回复完成才合成 | 首声等待长，不能满足边聊边听的目标 |
| 首次即采用全双工语音通话 | 引入 ASR、回声消除、端点检测和中断协议，超出文字聊天实时 TTS 范围 |
| 聊天另建模型、凭据和音频系统 | 重复成本与缓存规则，破坏已有密钥和协议边界 |

## 代价与范围

需要新增角色/会话修订、消息变体、可见性和记忆依赖、轮次状态及分句播放清单，也需要从现有章正文播放器抽取可复用能力。实施前没有轮次金额预算和聊天声音计划，书库备份也需扩展；本轮实现了聊天预算、声音子集与备份扩展，但写作/整章金额预算和真实听感/时延仍未验收。

人数、队列和延迟数值是初始设计；更改时同步 PRD、工程说明、合同和验收。现已沿现有合同生成链路增加实际 API 与 Alembic 0004，没有新增运行时依赖、自治框架或真实模型调用，不承诺具体账号具备低延迟/情绪控制能力。

## 验证与迁移

实施时先检查实际 schema head 和现有数据，新增 Alembic 迁移扩展角色、会话、消息、来源/可见性和播放索引，不复用或重建旧版本号。升级前用 SQLite backup API 做一致性备份，验证旧作品、分支、候选、配置、音频仍可读取；故障注入保证失败回滚。将来引入声音绑定作用域时，已有书籍声音设置映射至 book_character，不按名字推断映射。不触碰用户正式书库。

确定性测试覆盖：无模型人设、单聊/群聊、非法调度、同名成员、人设/成员变更、跨角色/会话隔离、加入前摘要、变体选择、重复请求、UTF-16/code point、封句范围、TTS 失败、背压、停止后迟到事件、进程退出和备份恢复。追加 AC-32 至 AC-49 界面路径。

真实验收另记录最短足够样本的模型/区域/音色、用量、首 token、首句封句、首声、取消静音和原生 WKWebView 播放时序；人工检查人设与听感。没有凭据时仅报告替身结果，不能宣称真实服务通过。具体已执行项与未验证项以 [验收记录 0004](../evaluations/0004-roleplay.md) 为准。

## 2026-10-17 实施记录

- 新增 `roleplay/domain.py`、合同模型及 0004 迁移：角色根/人设修订、会话根/快照、不可变消息、记忆来源、轮次检查点和本地幂等操作。`Book` 约束不变；会话成员保存稳定 ID、加入序号、人设修订与声音快照。
- 流式草稿保存在轮次检查点，完整/中断后追加不可变消息修订。快照只选择完整路径；编辑/换变体截断当前路径，旧分支可从历史找回。会话修订与角色库更新分开，用户身份也须明确应用新版。
- 调度、上下文、预算均在 Python：情境只取公开资料和所有当前成员共同可见的历史；每角色单独注入自己的人设。来源记忆须在所选路径、接收者和加入范围内；采用最近窗口与手动有来源记忆，不承诺自动语义提取。
- 复用 `ProviderService.workers`、传输/鉴权、全局语音锁和抽出的 `cached_audio`。每个实际调用先事务预留，记录 token/字符、可选金额与未知结果；金额使用用户为本轮填写的统一保守单价，不是提供商价格发现或厂商账单。写作/整章朗读尚未复用这套轮次金额预算。
- 封句片段的身份、范围、文本哈希及有效声音计划不变；播放状态单独记录在轮次片段项中。React 只请求已封句片段，三段待播上限在 Python 再校验；共用播放器解码/音频焦点，停止按钮先在前台静音，再持久化取消。旧 epoch、变体和外部修改后的头均被拒绝。新轮正常提交自身回复会推进自己的预期头。
- 本地规则提出语气；具体配置显式启用的 MiniMax `speech-2.6-hd/turbo` 支持核对过的 happy/sad/angry 和速度子集。其他标签/模型/服务回退普通语气，参数不写进 spoken text。人工音色与速度/语气覆盖优先；不自动切换服务或音色。
- 新 PNG 头像仅本地保存，验证字节/尺寸/CRC，不进入模型上下文。小说人物复制按选择字段和 reader_safe 位置预览；隐藏作者资料只允许显式进入本角色背景，不默认为群成员公开简介。
- 完整备份扩展至全部新实体；运行草稿冻结、中断来源与未知预算保留，服务端点/配置剔除。恢复核对角色、快照、消息、记忆、轮次和音频引用。当前备份仍限同 schema 0004；旧书库升级沿用 SQLite backup + DDL 事务，含失败回滚测试，不直接升级旧版本可移植备份。
- 原生替身验证使用独立重签副本、新测试书库和 loopback 固定文字/测试音；未读取真实凭据、未外传用户内容。原生测试音证明播放路径与打断，不证明真实语音自然度或延迟指标。
