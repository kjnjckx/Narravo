# ADR-0001：统一原创与导入作品，独立保存创作规划

- 日期：2026-10-16
- 状态：纳入 PRD v0.2 的设计基线，待实现验证
- 相关需求：PRD 第 6、9、12 节；AC-20 至 AC-31

## 问题

产品原有入口以导入小说为中心；用户明确要求同时支持从零开始写小说。原创作品没有源文件或前文，作者还需要提前规划尚未发生的事件。若沿用「所有作品必须有来源资产」「所有设定等同已发生事实」的假设，空白创作和无剧透续写会相互冲突。

## 决策

1. 保留 Book 为统一作品根实体，以 origin_type 区分 original/imported。原创作品的来源资产和哈希可空；不创建伪造 TXT，不另建一套原创数据库和编辑器。
2. 以同一事务创建默认分支、空正文快照、首章与稳定空段落锚点。无需模型即可手写和保存。
3. 创作简报、人物/世界观设定、大纲独立修订，通过 planning_manifest 与正文快照关联。章节结构同样受分支版本管理。
4. 用 artifact_kind 区分规划与正文生成，用 CandidateDecision 保存分项、部分和编辑后接纳，避免一种接纳操作污染另一类产物。
5. 明确 reader_safe、author_plan、full_rewrite 三种上下文策略；未来计划不是既成事实。朗读始终使用 reader_safe 视图。
6. 生成请求同时绑定正文和规划依赖。修改设定、大纲或章节结构时可检测旧候选冲突，不自动改写已经完成的正文。

## 比较过的替代方案

| 方案 | 未采用的原因 |
| --- | --- |
| 原创作品另建模块和数据库 | 重复编辑器、音频、版本与备份，容易产生两套不一致能力 |
| 用空 TXT 模拟新建 | 混淆来源与状态，掩盖空正文生命周期问题 |
| 大纲存入正文或通用 Memory 字段 | 难以分项接纳、版本化和约束事实可见性 |
| 所有模式都只允许读取前文 | 作者无法合理使用自己设计的未来剧情与世界观 |
| 所有模式都读取全书和全量设定 | 导入续写与听书可能提前泄露秘密，上下文成本不可控 |

## 代价与范围

需要新增规划修订、候选决策、上下文策略与依赖校验，但不改变 Tauri/React/Python/SQLite 技术栈。P0 只实现章节级大纲与逐次生成；多章编排、可视化关系和语义一致性检查保留在 P1。标签与提示不能保证模型输出绝不剧透，正文候选仍由用户检查接纳。

## 验证与迁移

当前只有文档，没有生产数据库，因此不执行任何迁移。首次建库即按来源可空和规划独立修订建模；若实施时已存在旧 schema，必须检查实际结构，编写 Alembic 迁移、备份和恢复测试，不能套用「当前无数据」的历史假设。

实现后分别验证无模型空白写作、LLM 开篇、分项接纳、分支隔离、规划依赖冲突、三种策略的上下文边界、备份恢复，以及原有导入听书路径。验证结果记录在评测文档中；本 ADR 不代表代码或测试已经完成。
