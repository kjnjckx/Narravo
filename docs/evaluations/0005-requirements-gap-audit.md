# PRD v0.3 需求缺口核对

- 日期：2026-10-17，Asia/Shanghai。
- 基线：PRD v0.3、README、验收记录 0001–0004，以及当前前端、合同、引擎、迁移和测试源码。
- 方法：逐项核对入口、请求合同与实际业务路径；补跑本地引擎/前端测试、类型检查及合同一致性。不是全量原生或真实模型验收。
- 工作区尚未初始化 Git，无法提供相对提交的差异检查；本次不修改业务实现或用户书库。

## 结论

当前是具备写作、导入、普通朗读和角色聊天闭环的开发版，扩展 P0 尚未全部完成。未完成项既包括缺少功能，也包括已有实现但缺少真实服务、质量、性能和发行验证。

不能把角色聊天的分句、多音色和轮次预算实现等同于小说情境朗读或写作金额预算已经完成。也不能因早期验收记录仍写着 EPUB/PDF、完整备份或聊天未实现，而将这些已落地能力重新列为缺失。

小说规划目前共用通用卡片，不能将可手写任意文字解释为所有结构化规划行为均已实现。四态章节状态在合同中实际为 `draft/revising/done` 三态，需要实现补齐或明确修订 PRD。

角色关系目前是文字描述，未提供群成员之间的稳定 ID 关系引用。该做法可表达外部人物关系，但与 §19.2 的成员关系引用目标仍有差距；关系图可视化本身是 P1，不能混为一项。

角色声音目前支持用户选择/预选默认声音，满足手选路径；根据人设及可用音色目录提出声音建议尚未实现。聊天语气已有本地规则和人工覆盖，不能因此列为“完全没有语气支持”；复杂语义表达属于质量和能力验证缺口。

聊天已有来源记忆、可见性过滤和上下文裁剪。没有自动摘要/语义记忆提取，不能声称完整长期记忆整理已完成；P0 手工记忆能力已经存在，跨会话复用和更丰富整理属于后续增强。

## 二、现有代码中的具体交互缺口

1. `apps/desktop/src/App.tsx` 的写作 `target()` 固定以正文总 code point 数作为 offset；`Editor.tsx` 没有向写作请求传递光标或正文选择。`full_rewrite` 当前是上下文读取范围，不是选段替换操作；引擎接纳仍执行插入。
2. `services/engine/src/narravo_engine/domain.py` 和 `providers/service.py` 的生成记录固定 `artifact_kind=prose`；现有 `planning.save` 是手工保存入口，没有规划候选生成/接纳路径。
3. `writing_accept` 在引擎允许继续接纳不重叠范围，但前端在 `generation.accepted=true` 后隐藏接纳编辑区。不能把引擎能力算成完整可操作 UI。
4. 小说重新点击生成会依据当前工作区组装输入，没有沿旧生成输入快照重试的请求合同。角色聊天的回复重试已有独立实现，不受这一结论影响。
5. 小说上下文将前文拼接后计算预算，超限要求缩小范围；没有小说摘要检索和自动裁剪流程。聊天上下文另有裁剪，不应混算。
6. 当前合同没有书籍/分支/会话删除、书签、阅读进度或用户缓存清理方法；角色归档、成员移出和章节移除已有实现。
7. 章节删除保留失效披露 ID，读者过滤保持隐藏，这是正确的保守行为；但尚无专门的“失效锚点待处理”修复流程。

## 四、兼容性边界和后续版本

- 当前可移植完整备份只接受 schema 0004；直接恢复 0003 备份未实现。旧 0003 书库打开时备份后迁移至 0004 已实现。这是两条不同路径。合并、加密备份是后续能力，不应自行提升为全部 P0 阻塞项。
- P1 未完成的主要范围：Windows、Markdown/DOCX 导入、创作模板、分卷/场景卡/关系图/伏笔板/时间线、多候选并列、完整章节/多章编排、一致性修复、语义检索、本地 TTS、音频/EPUB 导出、有限自主任务、外部角色卡、跨会话显式记忆复用、原生流式音频优化和 ASR/按键说话。
- 已有多个云 TTS adapter，因此“第二家云 TTS”不能算作完全没有接入代码；它们仍缺真实服务验收。
- OCR、声音克隆、同步、分支合并和全双工通话属于更后续/另行验证范围，不纳入当前 P0 完成率。
- PRD §8.2 尚保留“聊天分句管线尚未实现”的旧状态文字，与 §19.8、README 和验收 0004 不一致；本次以实际代码和后续记录为准。§19.6 对章正文播放与聊天实时语音的能力区分仍应保留。验收 0001–0003 的测试数和 schema 是历史记录，不代表当前状态。

## 六、建议推进顺序

1. 补齐 AI 结构化规划与条目接纳，再补光标续写/选段改写、原快照重试和候选部分接纳 UI，完成从零创作的原定 P0。
2. 补小说 Memory/Lorebook/摘要和中文检索、阅读进度/书签、章节目标及规划影响提示，解决长篇可用性。
3. 在普通音频底座上完成小说角色分析、多声音与人工纠正；同步补写作/整章预算、播放预取/跨章和数据清理。
4. 真实账号的最短虚构样本验收可穿插推进，随后完成质量集、原生时延、长时播放、VoiceOver、干净安装和签名公证。付费测试须按已有授权范围执行，不能由代码检查代替。
